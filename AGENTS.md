# AGENTS.md — правила работы над Beacon

## О проекте

Beacon — лёгкий SPA-мессенджер (пет-проект). Публикуется как статический сайт
на домене `beacon.testylemonad.ru` (файл `CNAME`). Данные и авторизация — Firebase
проекта `testy-beacon`, база — Realtime Database.

## Стек

- Чистый HTML + CSS + JavaScript, ES-модули.
- Без фреймворков, сборщика и `package.json`: проект запускается как статика.
- Firebase 13.0.0 подключается по CDN (`gstatic`) в модульном режиме.
- Используются только Firebase Authentication и Realtime Database; Analytics не нужен.
- `firebase-config.js` инициализирует `app`, `auth`, `db` и экспортирует их.

## Структура

- `index.html` — разметка всех экранов, модальных окон и подключение ассетов.
- `styles.css` — все стили, CSS-переменные тем, адаптивность.
- `app.js` — UI-слой и состояние: экраны, рендер, обработчики, модалки.
- `services/auth.js` — вход, регистрация, профиль, аккаунт.
- `services/chat.js` — чаты, сообщения, опросы, участники, права, пересылка.
- `services/sessions.js` — активные сессии устройства.
- `firebase-config.js` — конфигурация и инициализация Firebase.
- `structure-template.json` — эталон схемы Realtime Database.
- `RTDB-rules.json` — правила базы; публикует владелец вручную.
- `icon.png`, `CNAME`, `firebase-sdk-script.html` — служебные ассеты.
- `devpass.local.md` — локальные доступы; файл в `.gitignore`, в Git не попадает.

## Запуск и проверка

Локальный запуск из корня проекта:

```sh
python -m http.server 8000 --bind 127.0.0.1
```

Открыть `http://localhost:8000/`.

Сборки нет. Деплой — выкладка статических файлов, без bundle и compile-шага.

Проверка синтаксиса ES-модулей: скопировать файл во временный `.mjs` и выполнить
`node --check` (обычный `.js` Node может принять за CommonJS и ругаться на `import`).

Изменения проверять через реальный UI в браузере: сценарий, DOM, консоль.
Скриншоты могут быть недоступны — тогда проверять через DOM/evaluate.

## Правила интерфейса и продукта

- Все пользовательские тексты — на русском.
- Тёмная тема по умолчанию; светлая доступна и сохраняется в `localStorage`.
- Вёрстка адаптивная, десктоп и мобильные.
- Сохранять существующий визуальный язык и стиль, не делать редизайн без запроса.
- Вход принимает email или `@username`; регистрация — только по email.
- Активные сессии открываются отдельным модальным окном из «Настроек».
- Боты полностью бесплатны, без привязки карты; желательно, чтобы каждый
  пользователь мог создать бота сам.
- Все локальные ссылки на CSS/JS (в `index.html` и импорты модулей) имеют
  `?v=N`. При каждой правке поднимать версию и обновлять все ссылки согласованно,
  иначе браузер закеширует старые модули. На момент создания файла — `v31`.

## Архитектура и данные

- `structure-template.json` — источник схемы. При добавлении узлов/полей
  обновлять шаблон.
- `RTDB-rules.json` публикует владелец вручную. Прямого доступа к Firebase
  Console нет; нельзя считать, что изменённые правила уже применены.
- Не удалять и не изменять живые данные: реальные чаты, каналы, пользователей,
  сообщения, «Избранное», `@dev`, личные чаты владельца и Вани и т.п.
- Тесты — только на временных группах/каналах и фейковых пользователях.
  После теста удалять всё созданное: чат, сообщения, голоса, `user_reads`,
  `user_chat_meta`, `user_chats`, индекс юзернейма и прочие связанные узлы.
- Голоса опросов хранятся в `poll_votes/$chatId/$msgId/$uid`. При копировании
  или пересылке опроса голоса не переносить: у нового сообщения новый `id`.
- Держать изменения незакоммиченными, если коммит не запрошен явно.
- Не добавлять зависимости, сборщик или новые архитектурные слои без запроса.
- Следовать существующим именованию, структуре и паттернам кода.
- Не редактировать UTF-8 файлы через PowerShell `Get-Content -Raw` /
  `Set-Content`: это уже приводило к порче кириллицы. Пользоваться `edit`
  или .NET-записью UTF-8 без BOM. Проверять, что кириллица не перекодирована.
- Перед правкой читать окружающий код и не перезаписывать незакоммиченную
  работу пользователя.

## Отчёты

- Отчёты в `@dev` больше не отправлять. Писать всё сделанное владельцу в личные
  сообщения (@testylem); он сам решит, что публиковать.
- Отчёт — на русском, за подписью «Девелопер beacon», с указанием, по чьему
  запросу выполнена работа.
- Для отправки отчётов в мессенджер брать учётные данные из `devpass.local.md`.
  Никогда не записывать логин, пароль или иные доступы в публичные файлы,
  репозиторий, отчёты или чат.
- Не описывать работы по админ-правам и анти-эскалации в общих/публичных отчётах.
- После тестов сообщать, что временные данные удалены, а живые не тронуты.
