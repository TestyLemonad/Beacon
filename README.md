---

**Beacon** — пет-проект: небольшой, но полноценный SPA-мессенджер с личными
чатами, группами, каналами, опросами, комментариями, реакциями, поиском,
папками и отдельной страницей статистики. Данные и авторизация — Firebase
(Authentication + Realtime Database), интерфейс — ванильный JavaScript
с ES-модулями.

Регистрация закрыта: новый аккаунт можно создать только по инвайт-коду.

## Возможности

### Аккаунты и вход

- Вход по email или `@username` и паролю; вход через Google.
- Один аккаунт — два способа входа: Google можно привязать к аккаунту
  с паролем и отвязать обратно (если останется хотя бы один способ).
- Смена пароля с подтверждением текущего.
- Онбординг после первого входа: юзернейм, имя, фамилия, «о себе».
- Профиль с редактором аватарки: буква или эмодзи на сплошном цвете
  либо градиенте, с настройкой размера и палитрой.
- Настройка приватности последнего визита: «виден всем» или «скрыт».
- Список активных сессий с устройств и завершение лишних.
- Удаление аккаунта: профиль, настройки и подписки стираются, сообщения
  остаются с подписью «Удалённый аккаунт».
- Экраны для заблокированных и удалённых аккаунтов.

### Регистрация по инвайтам

- Регистрация полностью закрыта: без кода нельзя создать аккаунт
  ни по почте, ни через Google.
- Коды одноразовые, генерируются с криптостойкостью: 16 символов
  из алфавита без похожих букв (`I`, `L`, `O`, `U`, `0`, `1`).
- В базе не хранится открытый код — только соль и хэш, поэтому
  восстановить ссылку позже нельзя.
- Поддержка ссылок вида `/?invite_code=…` с автоподстановкой кода.
- Создание пачкой, заметки, отзыв, статусы «активен / использован /
  отозван / истёк».

### Общение

- Личные чаты, приватные и публичные группы, каналы, «Избранное».
- Личный чат создаётся детерминированно — дубликатов не бывает.
- Публичные группы и каналы находятся по `@username`.
- Каналы: подписка, предпросмотр до подписки, несколько администраторов,
  настройка «требуется подписка для чтения».
- Группы: владелец, администраторы, добавление и удаление участников,
  выход из группы.
- Сообщения: ответы, редактирование, удаление у всех или только у себя,
  пересылка, копирование текста, реакции.
- Закреплённые сообщения с плашкой в шапке чата.
- Черновики сообщений сохраняются по чатам.
- Опросы: до 10 вариантов, одиночный или множественный выбор.
- Комментарии к постам каналов и учёт уникальных просмотров.
- Отметки о прочтении, счётчики непрочитанных и разделитель
  «новые сообщения».
- «Печатает…», онлайн-статусы и последний визит.
- Чёрный список пользователей.
- Поиск по пользователям, каналам, публичным группам, своим чатам
  и сообщениям; фильтры по чату, автору и периоду.
- Папки чатов, архив и закрепление чатов в списке.
- Глубокие ссылки: `?u=@username`, `?s=запрос`,
  `?invite_code=КОД`.
- Тёмная и светлая темы; выбор сохраняется в `localStorage`.
- Адаптивная вёрстка для десктопа и мобильных.

### Статистика

Отдельная страница [`/dashboard/`](dashboard/index.html) с четырьмя вкладками:

| Вкладка        | Доступ              | Что показывает                                            |
| -------------- | ------------------- | --------------------------------------------------------- |
| Обзор          | без входа           | Пользователи, чаты, сообщения, активность, топ каналов    |
| Моя статистика | после входа         | Профиль, чаты, сообщения, каналы, вовлечённость, сессии   |
| Каналы         | после входа         | Аудитория, просмотры, посты, комментарии, реакции, опросы |
| Весь Beacon    | супер-администратор | Полная статистика мессенджера и публикация снимка         |

Публичные цифры берутся из `/public_stats` и читаются без авторизации.
Если правила базы ещё не опубликованы, дашборд показывает статический
снимок `dashboard/public-stats.json`.

### Администрирование

Для супер-администраторов предусмотрены инвайт-коды, резервирование
юзернеймов, дополнительные юзернеймы-алиасы, блокировка и удаление
аккаунтов, удаление чужих чатов и сообщений. Права проверяются правилами
Realtime Database, а не только интерфейсом.

## Быстрый старт

### Что нужно

- Python 3 или любой статический HTTP-сервер.
- Современный браузер с поддержкой ES-модулей.
- Интернет: Firebase SDK и данные загружаются с внешних доменов.

### Запуск

Из корня проекта:

```sh
python -m http.server 8000 --bind 127.0.0.1
```

Открыть:

- приложение — <http://localhost:8000/>;
- статистику — <http://localhost:8000/dashboard/>.

Устанавливать зависимости и собирать проект не нужно.

Открывать `index.html` двойным кликом (`file://`) не стоит: ES-модули,
Firebase Auth и Web Crypto требуют нормального HTTP-происхождения.
Для входа через Google `localhost` должен быть в списке авторизованных
доменов Firebase. Инвайт-коды используют `crypto.subtle`, поэтому нужен
`localhost` или HTTPS — на произвольном HTTP-адресе в локальной сети
браузер может запретить криптографию.

### Проверка синтаксиса модулей

Node.js не всегда понимает `.js` с `import` как ES-модуль. Надёжный способ:

```sh
copy app.js app.check.mjs
node --check app.check.mjs
```

Так же можно проверить любой файл из `services/` или `dashboard/`.
После проверки временный `.mjs` удалить.

## Firebase

Проект использует Firebase-проект `testy-beacon`:

- **Authentication** — Email/Password и Google.
- **Realtime Database** — все данные приложения.
- **Analytics** — не используется.

Конфигурация лежит в `firebase-config.js`. Файл экспортирует готовые
экземпляры `app`, `auth` и `db`, которые импортируют сервисы.

Веб-конфигурация Firebase не является секретом: она всё равно попадает
в браузер. Реальная защита данных — правила Realtime Database.

### Правила базы

`RTDB-rules.json` — исходник правил в репозитории, но он **не применяется
автоматически**. Владелец публикует правила вручную через Firebase Console.
Пока правила не опубликованы, часть функций (инвайты, статистика,
резервирование юзернеймов) может отвечать отказом в доступе.

При изменении схемы нужно согласованно обновлять:

1. `structure-template.json` — эталон структуры;
2. `RTDB-rules.json` — правила доступа и валидацию;
3. код сервисов, который читает и пишет новые поля.

### Схема

`structure-template.json` — не рабочие данные, а пример со всеми узлами
и полями. Он используется как документация и ориентир при доработках.
Реальные данные проекта не удаляются и не переписываются ради примеров.

## Архитектура

### Поток данных

```text
index.html
   │
   ▼
app.js ──────────────► services/*.js ──────► firebase-config.js ──► Firebase
   │                        │
   │                        └── Auth + Realtime Database
   ▼
DOM: экраны, список чатов, сообщения, модальные окна

dashboard/index.html
   │
   ▼
dashboard.js ─────────► services/stats.js ──► services/stats-core.js
                                │
                                └── Firebase
```

- `app.js` — единственный UI-слой. Он держит состояние, подписки,
  рендер и обработчики, но не работает с Firebase напрямую.
- `services/*.js` — работа с Firebase и бизнес-правила. Модули не рендерят
  интерфейс, а возвращают данные или промисы; браузерные API вроде
  `localStorage` и `visibilitychange` используются только там, где это
  часть логики (сессии, инвайты).
- `firebase-config.js` — единственная точка инициализации Firebase.
- `services/stats-core.js` — чистые функции: получают уже загруженные
  данные и считают числа. Одинаково используются дашбордом и снимком
  публичной статистики.

### Экраны и роутинг

Роутинг основан на состоянии Firebase Auth:

1. **Авторизация** — вход или регистрация.
2. **Онбординг** — заполнение профиля, если он ещё не готов.
3. **Инвайт-гейт** — аккаунт вошёл, но регистрация без приглашения
   запрещена.
4. **Мессенджер** — основной экран.
5. **Бан / удалённый аккаунт** — отдельные экраны блокировки.

Переходы выполняет `handleAuthChange` / `routeSignedInUser` в `app.js`.

### Состояние и подписки

Состояние приложения — один объект `state` в `app.js`: профиль, карта
чатов, активный чат, сообщения, поиск, настройки, счётчики, данные
опроса и комментариев. Отдельно хранится реестр подписок
`state.subscriptions`.

Жизненный цикл:

- `startSubscriptions()` подписывается на список чатов, настройки,
  присутствие, баны, профили и алиасы;
- `setupChatScoped()` подписывается на данные открытого чата:
  «печатает…», голоса опросов, комментарии, просмотры;
- `teardownSubscriptions()` и `clearChatScoped()` снимают подписки,
  чтобы не держать лишние соединения и не обновлять невидимый чат.

Любое изменение в Realtime Database приходит через `onValue`, обновляет
`state` и вызывает точечный рендер. Отдельного глобального
перерисовывания всего приложения нет.

### Глубокие ссылки

- `/?u=@username` — открыть человека, канал или публичную группу.
- `/?s=запрос` — открыть глобальный поиск.
- `/?invite_code=КОД` — подставить инвайт-код на экране регистрации.

Параметры синхронизируются с адресной строкой через `history.replaceState`,
поэтому ссылкой можно поделиться, а история браузера не засоряется.

### Статистика

`dashboard.js` лениво подключает Firebase: вкладка «Обзор» должна
открываться даже при недоступном CDN, показывая сохранённый
`public-stats.json`. Остальные вкладки требуют Firebase и входа.

`services/stats.js` читает только те узлы, на которые хватает прав,
и использует ограниченный параллелизм, чтобы не открывать сотни
соединений сразу. Расчёты вынесены в `stats-core.js`.

## Модель данных

Все данные лежат в Realtime Database. Время — unix-секунды.
Основные узлы:

| Узел                                       | Назначение                                          |
| ------------------------------------------ | --------------------------------------------------- |
| `users/$uid`                               | Профиль: юзернейм, имя, фамилия, био, аватар, email |
| `usernames/$name`                          | Индекс `@username → uid`                            |
| `login_index/$name`                        | Индекс входа: `{ uid, email }`                      |
| `reserved_usernames/$name`                 | Зарезервированные имена                             |
| `username_aliases/$name`                   | Дополнительные имена: `{ type, target, at, by }`    |
| `sessions/$uid/$sessionId`                 | Активные сессии устройства                          |
| `user_blocks/$uid/$blockedUid`             | Чёрный список                                       |
| `chats/$chatId`                            | Чат, группа или канал                               |
| `channel_usernames/$name`                  | Индекс `@username → chatId` для каналов             |
| `group_usernames/$name`                    | Индекс `@username → chatId` для публичных групп     |
| `messages/$chatId/$msgId`                  | Сообщения чата                                      |
| `user_chats/$uid/$chatId`                  | Список чатов пользователя                           |
| `user_message_deletes/$uid/$chatId/$msgId` | «Удалено только у меня»                             |
| `presence/$uid`                            | `{ online, lastSeen }`                              |
| `user_settings/$uid`                       | Приватность, режим администратора, скрытие промо    |
| `user_reads/$uid/$chatId`                  | Докуда дочитано                                     |
| `typing/$chatId/$uid`                      | «Печатает…» с TTL                                   |
| `poll_votes/$chatId/$msgId/$uid`           | Голоса в опросах                                    |
| `comments/$chatId/$postId/$commentId`      | Комментарии к постам                                |
| `views/$chatId/$msgId/$uid`                | Уникальные просмотры                                |
| `user_chat_meta/$uid/$chatId`              | Архив, закрепление, папки                           |
| `user_folders/$uid/$folderId`              | Папки чатов                                         |
| `root_admins/$uid`                         | Супер-администраторы                                |
| `invite_codes/$codeKey`                    | Соль и хэш инвайт-кода                              |
| `invite_redemptions/$codeKey`              | Кто и когда использовал код                         |
| `user_invites/$uid`                        | Подтверждение, что аккаунт пришёл по инвайту        |
| `banned_users/$uid`                        | Заблокированные пользователи                        |
| `deleted_users/$uid`                       | Удалённые аккаунты                                  |
| `public_stats`                             | Публичный снимок статистики                         |

### Типы чатов

| `type`    | Особенности                                                 |
| --------- | ----------------------------------------------------------- |
| `private` | Два участника, детерминированный `chatId`                   |
| `group`   | `groupType: private \| public`, владелец, админы, участники |
| `channel` | Владелец, админы, подписчики, счётчик подписчиков           |
| `saved`   | «Избранное» пользователя (`saved_$uid`)                     |

### Сообщение

```json
{
    "sender": "uid",
    "text": "Текст сообщения",
    "timestamp": 1728723605,
    "editedAt": 1728723950,
    "replyTo": {
        "msgId": "msg_1",
        "sender": "uid",
        "text": "Фрагмент исходного сообщения"
    },
    "forwardedFrom": {
        "uid": "uid",
        "name": "Имя отправителя"
    },
    "reactions": {
        "👍": { "uid": true }
    },
    "poll": {
        "question": "Вопрос",
        "multiple": false,
        "options": [
            { "id": "o1", "text": "Вариант 1" },
            { "id": "o2", "text": "Вариант 2" }
        ]
    }
}
```

Голоса опросов лежат отдельно, в `poll_votes/$chatId/$msgId/$uid`.
При пересылке или копировании опроса голоса не переносятся: у нового
сообщения новый `id`.

| Гость               | Войти, зарегистрироваться по инвайту, смотреть публичную статистику     |
| Пользователь        | Чаты, сообщения, опросы, реакции, профиль, настройки                    |

Интерфейс лишь подсказывает, что доступно, но не заменяет проверки
на сервере.

## Разработка

### Правила проекта

- Все пользовательские тексты — на русском.
- Тёмная тема по умолчанию, светлая сохраняется в `localStorage`.
- Сохранять существующий визуальный язык: это не редизайн-проект.
- Не добавлять фреймворки, сборщик, `package.json` и новые
  архитектурные слои без запроса.
- Следовать существующим именованию, структуре и паттернам кода.
- Не удалять и не изменять живые данные: реальные чаты, каналы,
  пользователей, сообщения и «Избранное».
- Тесты — только на временных чатах и фейковых пользователях.
  После теста удалять всё созданное: чат, сообщения, голоса,
  `user_reads`, `user_chat_meta`, `user_chats`, индексы юзернеймов.
- Держать изменения незакоммиченными, если коммит не запрошен явно.

### Кеширование и версии

Все локальные ссылки на CSS и JS имеют параметр `?v=N`:

- `index.html`;
- `dashboard/index.html`;
- импорты в `app.js`;
- импорты внутри `services/*.js`;
- динамические импорты и `fetch` в `dashboard/dashboard.js`.

При каждой правке нужно поднять номер
и обновить **все** ссылки согласованно. Иначе браузер закеширует
старые модули, и приложение будет вести себя непредсказуемо.

Найти все места:

```powershell
Get-ChildItem -Recurse -Include *.js,*.html | Select-String '\?v='
```

## Ограничения

- **Регистрация закрыта.** Новый аккаунт возможен только по инвайт-коду.
- **Нет вложений.** Сообщения текстовые: файлы, изображения, голосовые
  и видео не поддерживаются. Аватарки генерируются из буквы или эмодзи,
  а не загружаются.
- **Нет push-уведомлений.** Приложение не просит разрешение на уведомления
  и не работает как PWA.
- **Сессии отзываются «мягко».** Клиентский Firebase SDK не умеет
  отзывать refresh-токены. Запись `revokedAt` видит другое устройство,
  и оно выходит из аккаунта при следующем подключении. Полный отзыв
  возможен только через Admin SDK или Cloud Functions.
- **Инвайт-код нельзя восстановить.** В базе только соль и хэш; ссылку
  нужно сохранить сразу после создания.
- **Поиск по сообщениям — клиентский.** Он работает по загруженной
  истории чатов, а не по полнотекстовому индексу сервера.
- **Статистика читает много узлов.** На большой базе загрузка дашборда
  может быть небыстрой: вычисления идут в браузере.
- **Публичная статистика обновляется вручную.** Пока супер-администратор
  не опубликует снимок, вкладка «Обзор» показывает старые данные
  или статический `public-stats.json`.
- **Правила базы не применяются сами.** Изменения в `RTDB-rules.json`
  нужно опубликовать вручную.

## FAQ

**Как получить доступ к Beacon?**
Нужен инвайт-код от администратора. Откройте ссылку-приглашение или
введите код на экране регистрации. Без кода создать аккаунт нельзя.

**Почему вход через Google не открывается?**
Проверьте, что домен добавлен в Authorized domains в Firebase
Authentication и что браузер не блокирует всплывающее окно.

**Почему после правки файлов браузер показывает старое поведение?**
Не обновлён параметр `?v=N`. Поднимите версию во всех ссылках
и перезагрузите страницу с очисткой кеша.

**Почему инвайт-код не работает?**
Код одноразовый. Он мог быть использован, отозван или просрочен.
Если в базе ещё не опубликованы актуальные правила, приложение
сообщит об отказе в доступе.

**Где смотреть статистику?**
На `/dashboard/`. Публичный обзор открывается без входа, личные вкладки —
после входа, «Весь Beacon» — только для супер-администраторов.

**Почему изменения в правилах базы не подействовали?**
`RTDB-rules.json` — это файл в репозитории, а не автоматический деплой.
Правила публикует владелец проекта вручную.

**Можно ли использовать проект как основу для своего мессенджера?**
Это личный пет-проект. Лицензия в репозитории не указана; перед
переиспользованием кода свяжитесь с автором.
